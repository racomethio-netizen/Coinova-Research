## 2. Findings

### Critical

* **C1. Kill switch is not durable.** Its state lives only in Redis
  (`nexus:kill_switch`). Render's free Key Value does not persist data (my
  understanding of Render's free plan; not re-checked today). A Redis restart therefore clears an engaged kill switch
  silently. The trader's drawdown shutdown also writes no audit row, so nothing records it.
  Reads fail closed only when Redis is *unreachable*, not when the key is missing.
* **C2. Kill switch only blocks new entries.** It does not cancel resting entry orders,
  does not report exchange position state, and has no "close positions safely" action
  (Step 13 items 2-5).

### High

* **H1. No strategy is validated.** All six fail out-of-sample (expectancy -0.30% to
  -0.53% per trade). Correct behaviour is "no trade", but the platform produces no paper
  evidence until something passes. Not a bug; a research gap.
* **H2. Regime gating is not used for strategy selection.** `nexus_strategies.regime`
  classifies, but the trader does not disable strategies outside their validated regimes.
* **H3. Correlated-exposure limit is implemented but not wired** (`nexus_risk.correlation`
  is never called by the trader).
* **H4. Single shared process on a free instance.** API + market data + trader + notifier +
  news + X in one 512 MB process; free plan sleeps (kept awake by a self-request);
  Render's shared outbound IP got a Binance -1003 IP ban (until 2026-11-23 06:38 UTC).
  A dedicated-IP host is the durable fix (owner decision, costs money).

### Medium

* **M1. Paper engine realism:** no latency, missed-fill, outage or (spot) funding
  simulation; no execution-quality report.
* **M2. No agent layer:** analysis exists as deterministic modules, but no Technical /
  Quant / Derivatives / Sentiment / Portfolio agents producing a single explained trade
  proposal, and no Trade Review classification of closed trades.
* **M3. Derivatives:** funding and open interest now fetched live; no OI history, basis or
  liquidation feed.
* **M4. Dashboard:** no trade-proposal view, no News page, no Settings page, kill switch
  UI lacks the new actions; data is polled, not pushed (no WebSocket to the browser).
* **M5. Requested paper risk profile differs** from current defaults (current 0.5% / 2% /
  4% / 2 positions; requested 0.25% / 1% / 3% / 3 positions, 1x).

### Low

* Strategy library lacks VWAP, volatility breakout, order-flow imbalance, funding and
  liquidation strategies.
* `scripts/test.sh` lists mypy packages by hand (easy to forget a new package).

### Security review (no exposure found)

* No secrets in git: only `.env.example` and test fixtures. A hygiene test scans for key patterns.
* Exchange keys: AES-GCM encrypted with key rotation, TOTP step-up to add or test, never
  returned to the browser, fingerprint only; production keys with withdrawal permission
  are refused.
* Logs: redaction processor; tests confirm secrets do not appear.
* Auth: Argon2, TOTP, session cookies, CSRF header + Origin check, owner-only mutations,
  append-only audit log (trigger-enforced). Supabase: RLS on every table, anon and
  authenticated revoked.
* Live trading: six independent gates (env x3, prod env, TOTP + phrase owner approval
  in the DB, kill switch clear). Not enabled anywhere.

## 3. Implementation plan

Each phase: explain, list risks, implement, test, verify, document. Trading behaviour on
the server changes only with the owner's explicit approval.

| Phase | Content | Risk notes |
|---|---|---|
| **1 Safety foundations** | C1 durable kill switch (audit-log backed, restored to Redis on start and every trader cycle, fail closed); C2 kill-switch actions: block, cancel resting entry orders, report positions, optional close-all with typed confirmation (live), apply the requested paper risk profile (M5) | changes paper behaviour (owner asked for this profile) |
| 2 Risk wiring | H2 regime gate per strategy, H3 correlated exposure, cooldown after a stop-out, slippage limit on fills | can only reduce trading |
| 3 Agents + proposals | deterministic agents (technical, quant, derivatives, sentiment, portfolio) -> one proposal with evidence, contradictions, reasons to reject; independent Risk Manager verdict; Trade Review classifier; dashboard view | no LLM in the decision path; "no trade" is a first-class result |
| 4 Paper realism | latency, missed fills, outage injection, partial-fill reporting, execution-quality report | paper results get more conservative |
| 5 Derivatives data | OI history, basis, liquidation stream (`!forceOrder@arr`) | public data only |
| 6 New strategies | VWAP, volatility breakout, order-flow imbalance, funding, liquidation; each pre-registered, walk-forward, fees/slippage/funding | most will likely fail; nothing is enabled without passing |
| 7 Dashboard | 15-page structure, WebSocket push, News and Settings pages, proposal and kill-switch UIs | |
| 8 Failure tests | complete the scenario list (Step 14) | |
| Infra (owner) | Standard plan or a dedicated-IP host | costs money; owner decision |
